# نظام OSLO لإدخال منتجات سلة - نسخة الويب

نسخة ويب عربية متعددة المستخدمين، بكتالوج مشترك، وملف Excel قابل للتنزيل ومتوافق مع ترتيب أعمدة قالب البرنامج المكتبي.

## التشغيل محليًا للتجربة

1. ثبّت Python 3.10 أو أحدث.
2. من هذا المجلد أنشئ بيئة افتراضية وثبّت الحزم:

   ```powershell
   py -m venv .venv
   .\.venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   Copy-Item .env.example .env
   ```

3. ضع كلمة مرور مشتركة في `APP_PASSWORD`، وأنشئ قيمة عشوائية طويلة لـ `SESSION_SECRET`.
4. شغّل الخادم:

   ```powershell
   uvicorn app:app --host 127.0.0.1 --port 8000
   ```

5. افتح `http://127.0.0.1:8000`.

## النشر على Render

1. أنشئ خدمة **Web Service** واربط المستودع `O-alhakami/OSLO.PRO` من GitHub.
2. عيّن **Root Directory** إلى `salla_web`، لأن ملفات تطبيق الويب موجودة في هذا المجلد داخل المستودع.
3. شغّل التطبيق على الخطة المجانية أو المدفوعة باستخدام:
   - **Build Command:** `pip install -r requirements.txt`
   - **Start Command:** `uvicorn app:app --host 0.0.0.0 --port $PORT`
4. في **Environment Variables** أضف:
   - `APP_PASSWORD`: كلمة المرور المشتركة لفريق العمل.
   - `SESSION_SECRET`: قيمة عشوائية سرية طويلة لا تقل عن 32 محرفًا.
   - `DATABASE_PATH`: `/tmp/products.sqlite3` للخطة المجانية.
   - `COOKIE_SECURE`: `true`
5. اضغط **Create Web Service**، انتظر نجاح النشر، ثم افتح رابط `onrender.com` وسجّل الدخول بكلمة المرور.

### التخزين والبيانات على الخطة المجانية

- ستعمل الخدمة المجانية دون قرص دائم. إذا كان `DATABASE_PATH` مضبوطًا على `/var/data/products.sqlite3` ولم يكن المسار متاحًا، ينتقل التطبيق تلقائيًا إلى مجلد مؤقت قابل للكتابة، ويظهر تحذير بذلك في سجل Render وداخل الموقع.
- التخزين المؤقت **ليس دائمًا**: قد يمسح Render الملفات عند إعادة تشغيل الخدمة أو إيقاظها بعد السكون أو نشر إصدار جديد. نزّل ملف Excel بانتظام واحتفظ به خارج Render؛ ثم أعد استيراده عند الحاجة. هذا حل تجريبي منخفض التكلفة وليس ضمانًا لحفظ بيانات المخزون.
- الخدمة المجانية قد تدخل في وضع السكون بعد فترة من عدم الاستخدام، ولذلك قد يتأخر أول طلب عند إيقاظها.

### حفظ دائم على خطة مدفوعة (اختياري)

للاحتفاظ بقاعدة البيانات على Render، اختر خطة مدفوعة تدعم الأقراص الدائمة، ثم أضف قرصًا:
   - **Mount Path:** `/var/data`
   - **Size:** `1 GB` كبداية
ثم غيّر `DATABASE_PATH` إلى `/var/data/products.sqlite3`. الأسرار في إعدادات Render لا تضاف إلى GitHub.

### الخدمات الاختيارية

- ميزة Gemini: أضف `GEMINI_API_KEY` من Google AI Studio إلى Environment في Render.
- رفع الصور: أضف `CLOUDINARY_CLOUD_NAME` و`CLOUDINARY_API_KEY` و`CLOUDINARY_API_SECRET`.
- لا يحتاج الموظفون إلى تثبيت إضافات أو إدخال مفاتيح API على أجهزتهم. من دون هذه الأسرار تعمل إدارة المنتجات واستيراد/تصدير Excel؛ تتوقف فقط الميزة التابعة للخدمة غير المضبوطة.

## الوظائف

- إدخال بيانات المنتجات والقيم الافتراضية، وتوليد SKU تلقائيًا.
- استخراج بيانات المنتج عبر Gemini، مع هامش السعر الثابت نفسه، وقيم العلامة والتصنيف والحقول الثابتة كما في البرنامج المكتبي.
- اختيار صور متعددة، معاينتها وإزالتها، رفعها إلى Cloudinary، وحفظ الروابط مفصولة بفواصل.
- البحث في المنتجات، تعديل SKU، حذف المحدد، وإعادة ترقيم SKUs.
- استيراد ملف Excel الحالي لإضافة منتجاته إلى الكتالوج المشترك، وتنزيل قالب فارغ أو ملف المنتجات بأعمدة سلة الرسمية الـ40 ثم أعمدة الكمية وSEO الإضافية، وورقة التصنيفات.

تُحفظ المنتجات في SQLite لتعمل قاعدة مشتركة على خادم واحد بقرص دائم. الملف المصدر للبرنامج المكتبي لم يُعدّل.
